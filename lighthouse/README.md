# Lighthouse — практические работы №13–14

В проекте сохранены HTML-отчёты Lighthouse, полученные при предыдущей проверке:

- `index-mobile-report.html`
- `catalog-mobile-report.html`
- `product-mobile-report.html`
- `contacts-mobile-report.html`
- `order-mobile-report.html`

**Важно:** эти отчёты относятся к предыдущей версии проекта. После обновления `alt`, JSON-LD, `sitemap.xml` и других файлов необходимо повторить аудит, чтобы получить актуальные результаты. Новые баллы здесь заранее не указаны.

## Как запустить актуальный Lighthouse

1. Запустите папку DOMA через Live Server в VS Code.
2. Откройте страницу по адресу `http://127.0.0.1:5500/...` в Google Chrome.
3. Нажмите `F12` и выберите вкладку **Lighthouse**.
4. Выберите режим **Navigation**, устройство **Mobile**.
5. Отметьте категории **Accessibility** и **SEO**. При необходимости добавьте Performance и Best Practices.
6. Нажмите **Analyze page load**.
7. После завершения проверки откройте меню отчёта и выберите **Save as HTML**.
8. Сохраните отчёт в эту папку, заменив старый файл с тем же именем.

Рекомендуется повторить проверку для `index.html`, `catalog.html`, `product.html` и `order.html`.

## Что дополнительно проверено в исходниках

- Все статические изображения HTML имеют непустой `alt`.
- В массивах данных 12 товаров есть подробные описания `imageAlt` / `alt`.
- Скрипты `main.js`, `kr3.js` и `order.js` передают эти описания в `img.alt` или атрибут `alt` создаваемого изображения.
- JSON-LD `Product` обновляется при выборе товара на `product.html`.
- XML-карта сайта проходит синтаксический разбор, а `robots.txt` содержит ссылку на неё.

Статические проверки не заменяют повторный браузерный Lighthouse-аудит и ручную проверку сайта клавиатурой.
